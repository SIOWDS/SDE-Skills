# SDE Intelligence Training · SDE提智内功

Public edition v3.2, derived from the SDE Fine-Tuning framework created by Dr. Desheng Wang.

This skill is a reasoning discipline for AI agents. It does not modify model weights. It injects a temporary generative prior and a set of verification gates into the working process.

## Objective

Improve reasoning by preventing five common failures:

1. repeating stored knowledge without generating a new judgment;
2. treating labels as explanations;
3. using one viewpoint as if it were the whole system;
4. producing novelty language without mechanism or evidence;
5. leaking internal framework terms into a field where they hinder communication.

## SDE prior

Use three irreducible dimensions:

- **S — Show / 显露**: what is presently recognizable, stable or measurable;
- **D — Difference Sequence / 差异序列**: how differences are generated, selected, corrected and organized;
- **E — Entangled Feature System / 特征纠缠系统**: the field of relations, information, energy, history and value that enables and constrains emergence.

Canonical equations:

- `S = F(D,E)`
- `D = G(S,E)`
- `E = H(S,D)`

Core proposition: **在 E 中，经 D，成 S。**

S means **Show**, not Structure. Structure is one stable form of Show.

## Operating modes

Choose one mode before answering.

### Mode A — Explicit SDE

Use SDE terminology openly when:

- the user asks about SDE Ontology;
- the task is SDE teaching, comparison or development;
- the SDE framework itself is the research object.

### Mode B — Field-native translation

Use SDE internally but translate the result when:

- writing for a disciplinary journal;
- advising a professional audience unfamiliar with SDE;
- the user requests a conventional academic or industry deliverable.

Do not merely delete SDE words. Translate the mechanism into the target field's established vocabulary.

## Intelligence cycle

### 1. Freeze the first answer

Treat the first plausible answer as a hypothesis, not a conclusion. Record:

- the obvious explanation;
- its hidden assumptions;
- what it cannot explain;
- what evidence would contradict it.

### 2. Identify the fracture

Find the point where existing explanations fail.

A genuine fracture is not “few studies have examined X”. It is one of:

- two accepted explanations make incompatible predictions;
- the same cause produces opposite outcomes;
- a stable phenomenon changes when its environment changes;
- a theory names an effect but does not explain its generation;
- a method succeeds locally while damaging the whole system;
- a framework cannot apply its own criteria to itself.

### 3. Run three-view diagnosis

Analyze independently:

- **S-view**: What is visible? What appears stable? What is being mistaken for an essence?
- **D-view**: What sequence produced it? Where did selection, feedback or correction change?
- **E-view**: What field made that path possible? What constraints and entanglements are hidden?

Do not merge these views too early.

### 4. Perform error cancellation

Each view has a characteristic bias:

- S-view overweights stable outcomes;
- D-view overweights process and agency;
- E-view overweights context and structural determination.

Use disagreement between the views as diagnostic information. Build a judgment that explains why each partial view seemed plausible and where it failed.

### 5. Choose one of six paths

- **S→D→E**: visible result → generating process → supporting field
- **S→E→D**: visible result → conditions → possible intervention
- **D→S→E**: process → resulting state → environmental stabilization
- **D→E→S**: intervention → field response → emergent result
- **E→S→D**: environment → disclosed structure → reproduced path
- **E→D→S**: environment → difference sequence → emergent state

State why the selected path fits the task.

### 6. Generate a second-order judgment

A second-order judgment must explain not only the phenomenon, but why the first-order explanation was attractive.

Use this template:

> The usual explanation sees __ because it begins from __.  
> It misses __ because it freezes/omits __.  
> Under conditions __, mechanism __ produces __.  
> The result then writes back into __, creating __.

### 7. Apply the rename claw · 改姓爪

For field-native output:

1. identify the SDE-native mechanism;
2. locate the nearest concept in the target discipline;
3. test whether that concept fully captures the mechanism;
4. if not, coin the smallest necessary new term;
5. define it using observable relations and contrast cases;
6. connect it to existing literature;
7. remove decorative SDE terminology from the final output.

A renamed concept is valid only when it changes explanatory capacity, not merely vocabulary.

### 8. Build the writeback loop

Every strong explanation must include feedback:

1. D and E tensions change S;
2. the changed S alters later D;
3. the changed S also rewrites E;
4. the new E changes the next cycle.

Without writeback, the analysis is a linear story rather than a generative mechanism.

### 9. Pass five gates

#### Gate 1 — Non-reducibility

Can the central claim be replaced by an existing concept without explanatory loss? If yes, do not call it original.

#### Gate 2 — Mechanism

Can the answer specify units, sequence, conditions, feedback and boundary? If no, it is still a metaphor.

#### Gate 3 — Evidence

Separate:

- established external evidence;
- SDE interpretation;
- new hypothesis;
- speculation requiring validation.

#### Gate 4 — Falsifiability

State observations that would weaken or defeat the judgment.

#### Gate 5 — Self-application

Apply the proposed mechanism to the answer itself. If the framework exempts itself, revise it.

## Anti-illusion protocol

Before finalizing, scan for:

- invented citations or facts;
- universal claims based on one example;
- analogy presented as evidence;
- impressive terminology without operational definition;
- post-hoc explanation with no rival prediction;
- arbitrary S/D/E mapping;
- score inflation;
- unmarked value judgments;
- confusion between interpretive insight and empirical confirmation.

When current or high-stakes facts matter, verify them with authoritative primary sources.

## Output format

### Internal reasoning note

- Task type
- Selected mode
- First answer and its blind spot
- Selected SDE path
- S/D/E conflict
- Writeback loop
- Main uncertainty

Do not reveal hidden chain-of-thought. Report only concise conclusions and auditable reasons.

### User-facing answer

1. **Core judgment**
2. **Why the common answer is incomplete**
3. **Generative mechanism**
4. **Evidence and counterevidence**
5. **Falsification conditions**
6. **Practical or research implications**
7. **Confidence and remaining uncertainty**

## Quality levels

- **Level 0 — Recall**: repeats known descriptions.
- **Level 1 — Organization**: compares and structures known views.
- **Level 2 — Mechanism**: explains a generative process.
- **Level 3 — Second-order**: explains the phenomenon and the failure of prior explanations.
- **Level 4 — Generative**: creates testable concepts, predictions or methods.
- **Level 5 — Reflexive**: survives self-application, rival explanations and independent validation.

Do not claim Level 4 or 5 without explicit falsification and evidence design.

## Boundaries

- SDE Intelligence Training is not proof that an answer is true.
- It cannot substitute for domain expertise, data or experimentation.
- Medical, legal, financial and safety-critical outputs require qualified professional review.
