# Contributing to SDE Skills

Thank you for helping build an open, testable and useful SDE Skill ecosystem.

## Good contributions

- a new reusable SDE-based skill;
- a clearer or shorter workflow;
- translations;
- realistic test prompts and expected outcomes;
- evidence corrections;
- security or privacy fixes.

## Skill requirements

Every skill must:

1. live in `skills/<skill-name>/SKILL.md`;
2. use lowercase hyphenated naming;
3. include YAML frontmatter with `name` and `description`;
4. state triggers, workflow, outputs and quality boundaries;
5. avoid credentials, personal data and confidential material;
6. distinguish theoretical claims from externally established evidence;
7. include safety requirements for high-stakes domains.

Prefer a concise `SKILL.md`. Put detailed supporting material in `references/` only when necessary.

## Pull requests

Explain:

- what the skill does;
- why it is reusable;
- example trigger requests;
- how it was tested;
- limitations and safety considerations.

By contributing, you agree that your contribution may be distributed under the repository license.
